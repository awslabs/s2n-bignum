# Working on the FIPS 203 equivalence proofs

Goal: prove in HOL Light that the FIPS 203 model generated by the FIPS
pseudocode compiler (`common/fips203/generated/fips203_generated.ml`) computes the same
results as the handwritten model (`common/fips203.ml`, with lemmas in
`common/fips203_theory.ml`), for ML-KEM-512, -768 and -1024.

Repository root (the HOL working directory):
the root of the s2n-bignum checkout.
All paths below are relative to `common/fips203/generated/core/` unless
they start with `common/` or `arm/`.

## Files

- `base.ml`: loads both models, and the properties of the handwritten model
  (`common/fips20[23]/properties/`), into one session and defines the
  abstraction functions `fz`, `zarr`, `zpoly`, `zqlist`, `zq_list_ok`,
  `zvec`, `zmat`. Read it first.
- `interface.ml` (generated by `tools/gen_interface.py`; do not edit):
  every lemma that crosses a file boundary, as a term `NAME_STMT`, grouped
  by the file that must prove it.
- `stubs.ml`: `let NAME = mk_thm([], NAME_STMT)` for every interface lemma.
  DEVELOPMENT ONLY: it lets you use lemmas that other agents are still
  proving. Your servers preload it. `all.ml` never loads it.
- `check.ml`: run by `all.ml` at the end; fails unless every `NAME` is a
  theorem with no hypotheses whose conclusion is `NAME_STMT`.
- `all.ml`: loads base, interface, then the proof files in this order:
  `foundation.ml`, `bytes.ml`, `rq.ml`, `ntt.ml`, `nttinv.ml`,
  `sample_ntt.ml`, `tq.ml`, `kpke.ml`, `mlkem.ml`, `final.ml`, then
  `check.ml`.
- `tools/hol-server.sh`, `tools/holc.py`: HOL server and client (below).
- `tools/check-all.sh`: runs `all.ml` in a fresh HOL Light, no stubs.

## Rules

1. Prove every lemma you own as `let NAME = prove(NAME_STMT, tactic);;`
   in your file, using the statement from `interface.ml` unchanged.
2. If a statement you own is false or cannot be proved as stated (wrong
   length, missing hypothesis, wrong index), do NOT work around it. Send
   the main agent a message (SendMessage to `main`) with the reason, a
   counterexample if you have one, and the exact replacement statement you
   propose, then keep working on your other lemmas. The main agent updates
   `interface.ml` and tells everyone.
3. You may use interface lemmas owned by files EARLIER in the load order
   above (as stubs while you develop). Never use a lemma owned by your own
   file before it is proved, or one owned by a later file.
4. Local helper lemmas and definitions: prefix their names with your file
   tag in capitals (`FOUNDATION_`, `BYTES_`, `RQ_`, `NTT_`, `NTTINV_`,
   `SAMPLE_`, `TQ_`, `KPKE_`, `MLKEM_EQ_`; lower case for definitions,
   e.g. `ntt_layer`), so that the files never clash in `all.ml`.
5. No `mk_thm`, `CHEAT_TAC`, `new_axiom` or `new_constant` in your file.
   `tools/check-all.sh` rejects them, and `check.ml` fails unless HOL Light has
   exactly its three standard axioms.
6. Your file must load from the repository root with
   `loadt "common/fips203/generated/core/FILE.ml";;` in a session where
   `base.ml`, `interface.ml` and the earlier proof files are loaded. It must
   not load `stubs.ml`. If you need another HOL library or s2n-bignum
   file, `needs` it at the top of your file and mention it in your report.
7. Edit only your own proof file. Do not edit `base.ml`, `interface.ml`,
   `stubs.ml`, other agents' files, or anything outside this directory.
   Do not run git commands that change anything (no add/commit/stash/
   checkout/reset). Write scratch files under `/tmp/fips203-equiv/`.
8. Keep your file in a loadable state as you go: proved lemmas first,
   unfinished work at the end or in scratch files. Save often; other
   agents and the main agent may read it.

## Talking to HOL Light

Each agent has its own server; use only your port. It was started with
`base.ml`, `interface.ml` and `stubs.ml` preloaded and takes about 5
minutes to come up:

    tools/hol-server.sh wait PORT      # blocks until ready; shows preload errors

Send commands with the client (from this directory):

    python3 tools/holc.py -p PORT 'let th = prove(`1 + 1 = 2`, ARITH_TAC);;'
    python3 tools/holc.py -p PORT -f /tmp/fips203-equiv/try.ml   # whole file as one command
    python3 tools/holc.py -p PORT 'loadt "common/fips203/generated/core/FILE.ml";;'
    python3 tools/holc.py -p PORT -t 1200 '...'   # timeout in seconds (default 600)
    python3 tools/holc.py -p PORT --interrupt     # interrupt a runaway command

The goal stack works too (`g`, `e`, `b`, `p`, `top_thm`). Output prints
`RESULT:` or `ERROR:`; exit status 0/1/2 for success/error/timeout. Bind
results with `let x = ...;;` so that HOL does not print huge terms, and use
`-m N` to clip output. The server keeps its state between commands, so
reloading your file redefines your lemmas in place.

If your server dies or its state becomes unusable, restart it (5 minutes):

    tools/hol-server.sh stop PORT
    tools/hol-server.sh start PORT common/fips203/generated/core/base.ml \
      common/fips203/generated/core/interface.ml common/fips203/generated/core/stubs.ml
    tools/hol-server.sh wait PORT

When the main agent changes `interface.ml`, reload with
`loadt "common/fips203/generated/core/interface.ml";;` and
`loadt "common/fips203/generated/core/stubs.ml";;` (seconds).

## Reading the generated model

`common/fips203/generated/fips203_generated.ml` defines each FIPS 203 algorithm as a
monadic HOL function: results are `Value x`, `Fault e` or
`Nontermination`, sequenced with `native_bind`; loops are `native_foldl`
over a `native_schedule` of loop indices (ints); lists are read and written
with `typed_hol_read (native_list_index xs i)` and `native_list_update`;
`typed_hol_nominal_update` updates a field of a polynomial, vector or
matrix. Each constant `C` has the theorem `C_DEF`. Elements of Z_q are
`FIPS203_Zq (Residue n)`; `residue_of_int_mod v` reduces `v` mod the
modulus in its type. The prelude `common/fips203/generated/core/compiler/fips_hol_prelude.ml`
defines `isa_nat`, `isa_int_mod`, `isa_upt`, `isa_list_update`, etc.
Many constants exist once per parameter set (`..._MLKEM512_...`) or per
size (`BytesToBits_128_hol`); they differ only in numerals.

Useful handwritten-side facts: `common/fips203_theory.ml` has
`KPKE_KEYGEN_FIPS`, `KPKE_ENCRYPT_FIPS`, `KPKE_DECRYPT_FIPS` (NTT-domain
forms of K-PKE), `MLKEM_NTT_FORWARD`, `MLKEM_NTT_INV_EXPLICIT`,
`MLKEM_NTT_INV_COEFF`, `MLKEM_NTT_MULTIPLY`, `fips203_multiply_ntts`,
`MLKEM_DECODE_ENCODE*`, `NUM_OF_BYTELIST_MLKEM_ENCODE`, `MLKEM_EK_CHECK`,
`MLKEM_ROUND_UNIQUE`, and many small lemmas; grep it.

HOL Light sources (for library theorem names):
HOL Light's source directory (`$(dirname hol.sh)/../lib/hol_light` in the nix package)
(see `lists.ml`, `int.ml`, `Library/words.ml`, `Library/ringtheory.ml`,
`Library/isum.ml`). s2n-bignum's `common/` has more (e.g.
`common/int_linear.ml`: `INT_LINEAR_CONG_TAC`; `common/mlkem_mldsa.ml`:
`forward_ntt`, `FORWARD_NTT_CONV`, congruence/bound tactics).

## Proof style

- Avoid unrolling 256-iteration loops into huge terms. Prefer the loop
  lemmas in the foundation (`NATIVE_FOLDL_VALUE` with an invariant,
  `NATIVE_FOLDL_FILL`, `NATIVE_SCHEDULE_UPTO`, `NATIVE_SCHEDULE_STEP`) and
  reason about lists element-wise (`LIST_EQ`, `LENGTH_LIST_OF_SEQ`,
  `EL_LIST_OF_SEQ`, `EL_ISA_LIST_UPDATE`).
- Where a finite computation is the simplest route (e.g. 128 values of
  BitRev7, a 7-element schedule), `EXPAND_CASES_CONV`, `NUM_REDUCE_CONV`,
  `INT_REDUCE_CONV` and `WORD_REDUCE_CONV` work well.
- Prove one parameter set first, then make the tactic generic and reuse it
  for the other two.
- Move fast. Report blockers to `main` early instead of spending hours.

## Report

When done (or when you stop), reply with: the lemmas proved, anything
left unproved and why, helper names you added, extra `needs`, any
statement changes you requested, and how long your file takes to load.

## Where the properties of the handwritten model went

Lemmas that mention only the handwritten model are not proof steps of the
equivalence; they live next to the specification, in
`common/fips203/properties/` (`encoding.ml`, `compression.ml`,
`rq_ring.ml`, `ntt_*.ml`, `kpke_ntt_domain.ml`, `input_checks.ml`,
`sampling.ml`) and `common/fips202/properties/` (`keccak_*.ml`). Among them,
`sampling.ml` proves `SAMPLE_OK_ALL` and the two `keccak_*` files prove that
Keccak-f is a permutation, which is the argument of Barbosa and Schwabe,
"Kyber terminates" (ePrint 2023/708). `final.ml` removes the `sample_ok`
hypotheses of the earlier `*_EQUIV` lemmas with it. `base.ml` loads all of
these through the aggregators `fips20[23]_properties.ml`.
