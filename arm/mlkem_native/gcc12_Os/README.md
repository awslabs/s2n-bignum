# The gcc 12 -Os build

This directory is for mlkem-native's `libmlkem.so` built like the gcc 12
`-O2` one (see `../README.md`), but with `-Os`:
`binaries/aarch64/multilevel/gcc12/Os/libmlkem.so` in the `binary-v2.1`
branch of mlkem-native (commit `ce25e8a8d`, built from the v2.1.0
release, commit `4d69d6b03`, the source of the `-O2` build, SHA-256
`118cef71ac3d5b0ccd9d3d0edc6e7ded072d5cf9fab3f3c1b37d61719e26139c`, as
in `binaries/SHA256SUMS` and `binaries/builds.json` there). `libmlkem.S`
transcribes its image, from address 0 to the end of the read-only data
at `libmlkem_size` = 0x5c40, and `../../proofs/mlkem_native/gcc12_Os/`
has its layout (generated by `../gen_layout.py`), the definition of the
image and the proofs. All the functions are verified directly in the
image, as for `-O3`.

## Compared with gcc 12 -O2

The `-Os` binary has 129 functions: the 116 of the `-O2` binary and 13
static functions that gcc does not inline at `-Os`:

 - `mlk_zeroize` (8 copies, `mlk_zeroize_1` to `mlk_zeroize_8`, one for
   each translation unit that uses it) and `mlk_ct_memcmp` (3 copies),
   which the API functions call where `-O2` has their code inline;
 - `mlk_keccak_squeeze_once` and `mlk_keccak_squeezeblocks_x4`.

Of the 116 functions that `-O2` has, 33 have the same code at `-Os`, up
to the addresses: the same instructions, with the same branches, calls and
ADRP pairs. These are `keccakf1600x4_permute`, `_xor_bytes` and
`_extract_bytes`, `shake128_init`, `shake128x4_init`, `shake128_absorb_once`
and most of the `polyvec` functions that apply a polynomial function to
each polynomial. The others have different code, though two, `poly_tobytes`
and `shake128x4_absorb_once`, differ from `-O2` in one instruction.

The code differs from `-O2` and `-O3` as follows:

 - gcc does not vectorize at `-Os`. The polynomial functions are loops
   over 16-bit coefficients with `LDRH`, `LDRSH` and `STRH`, `mlkem_poly_ntt`
   and `mlkem_poly_invntt_tomont` are nested loops over the layers, the
   start of each block and the coefficients, and `mlkem_keccakf1600_xor_bytes`
   and `mlkem_keccakf1600_extract_bytes` are loops over bytes.
 - It makes constants with immediate operands instead of loading them,
   so the read-only data has 6 objects (23 at `-O2`, 40 at `-O3`), all
   with the contents they have at `-O2`.
 - It calls `memset` through the PLT where `-O2` stores zeros, in
   `mlkem_shake128_release`, `mlkem_shake128x4_release` and the clearing of
   the API functions.
 - `mlkem_shake256x4` divides with `UDIV`, which the other builds
   of mlkem-native do not use.

## The proofs

`../../proofs/mlkem_native/gcc12_Os/` has a spec file and a proof file for
each of the 129 functions, with the theorems that the `-O2` build has for
the function (`..._IMAGE_SUBROUTINE_CORRECT` and `..._SAFE`, and
`..._FULL` where callers need it, see `../README.md`), and `fips203.ml`
with the theorems of the API functions without the hypothesis that
SampleNTT terminates. The theorem names contain `GCC12_OS`, e.g.
`MLKEM_NATIVE_POLY_NTT_GCC12_OS_IMAGE_SUBROUTINE_CORRECT`; the files
`zeroize_1` to `zeroize_8`, `ct_memcmp_1` to `ct_memcmp_3`,
`keccak_squeeze_once` and `keccak_squeezeblocks_x4` are for the 13 new
functions, and `rej_uniform` is for `mlk_rej_uniform_c`.

The statements of the `-O2` build are the same, with these exceptions,
which come from the code:

 - The stack frames are those of the `-Os` code and its callees, e.g. 224
   bytes for `mlkem_keccakf1600_permute` (192 at `-O2`) and 1824 for
   `mlkem_shake256x4` (1792).
 - The theorems of constant time and memory safety list only the constants
   that the code reads, so those of the polynomial functions that load none
   at `-Os` have no read-only region.
 - `mlkem_poly_decompress_d5`, `_d10` and `_d11` have a stack frame and a
   stack guard, as `mlkem_poly_compress_d4` has at `-O2`.
 - The functions that call `memset` through the PLT, where `-O2` stores
   zeros, assume `memset_contract` (`memset_safety_contract` and
   `memset_full_contract` for the theorems of constant time and memory
   safety), as several functions do at `-O2`: these are
   `mlkem_shake128_release`, `mlk_keccak_absorb_once`, the SHA-3 and SHAKE
   functions, `mlk_zeroize_N` and, through them, the functions up to the API
   functions.

The proofs of the polynomial functions, the Keccak byte loops and the
functions that call the new static functions are new, since the code is
scalar and has different loops and calls. Those of the functions with the
same code as at `-O2` are the `-O2` proofs with the names changed. The
proofs use the tactics and lemmas of `../../proofs/mlkem_native/*.ml`,
`../../proofs/utils/mlkem_native*.ml` and `../../common` as the other
builds do; the ones that only the `-Os` code needs, e.g. for the loops of
`mlkem_poly_ntt` and for the four sampling loops of
`mlkem_poly_rej_uniform_x4`, are in its spec files.
