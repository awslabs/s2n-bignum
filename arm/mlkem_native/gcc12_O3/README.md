# The gcc 12 -O3 build

This directory is for mlkem-native's `libmlkem.so` built like the gcc 12
`-O2` one (see `../README.md`), but with `-O3`:
`binaries/multilevel/gcc12/O3/libmlkem.so` in the `binary` branch of
mlkem-native. `libmlkem.S` transcribes its image, from address 0 to the end
of the read-only data at `libmlkem_size` = 0x8c80, and
`../../proofs/mlkem_native/gcc12_O3/` has its layout (generated by
`../gen_layout.py`), the definition of the image and the proofs. All the
functions are verified directly in the image: unlike for `-O2`, there are
no separate transcriptions of single functions.

## Compared with gcc 12 -O2

Of the 116 functions of the `-O2` binary:

 - 70 have the same code at `-O3`, up to the addresses: the same
   instructions, with the same branches, calls and ADRP pairs;
 - 43 have different code, and the 3 static functions
   `mlk_rej_uniform_c.constprop.0`, `mlk_keccak_absorb_once` and
   `mlk_keccak_absorb_once_x4.constprop.0` are inlined into their
   callers, except that a specialized copy
   `mlk_keccak_absorb_once.constprop.1` remains, named
   `mlk_keccak_absorb_once` in the layout as at `-O2`.

The code that differs is mostly vectorized, and uses 18 kinds of
instructions (141 in all) that the model of AArch64 did not decode when
this build was started: LD2, ST2, LD3, ST3, LD4 and ST4 without an offset,
SHLL and SHLL2, UZP1 and UZP2 of 64-bit vectors, LDR of an H register, and
LDR and STR of a D register with a register offset.

Where a proof is the same as for `-O2` up to the names of the build, this
is noted below, as a candidate for sharing the proof between the builds.
