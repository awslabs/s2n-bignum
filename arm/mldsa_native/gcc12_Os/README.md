# The gcc 12 -Os build

This directory is for mldsa-native's `libmldsa.so` built like the gcc 12
`-O2` one (see `../README.md`), but with `-Os`:
`binaries/multilevel/gcc12/Os/libmldsa.so` in the `binary` branch of
mldsa-native (commit `65f9995`, "binaries: Rebuild the AArch64 matrix from
main"). Its `binaries/builds.json` records mldsa-native commit
`d38418ea3d4c` as the source of the whole matrix, the default
configuration (no `-DMLD_CONFIG_REDUCE_RAM`) and
`-Os -g -gdwarf-4 -gsplit-dwarf -fPIC`.
`libmldsa.S` transcribes its image, from address 0 to the end of the
read-only data at `libmldsa_size` = 0xa4dc, and
`../../proofs/mldsa_native/gcc12_Os/` has its layout (generated by
`../gen_layout.py`), the definition of the image and the proofs.

The SHA-256 hash of the binary, which matches that recorded in
`binaries/SHA256SUMS` of mldsa-native, is:

```
binaries/multilevel/gcc12/Os/libmldsa.so
  ee0e975d8c2e8920e4600e241f3bf8b2eb323a180c7181f4d926612d34503eea
```

To regenerate the files of the build, in the `arm` directory:

```
python3 mldsa_native/gen_libmldsa_s.py \
  <mldsa-native>/binaries/multilevel/gcc12/Os/libmldsa.so \
  mldsa_native_libmldsa_gcc12_Os "gcc 12, -Os" \
  binaries/multilevel/gcc12/Os/libmldsa.so $PWD/../include \
  > mldsa_native/gcc12_Os/libmldsa.S
python3 mldsa_native/gen_layout.py \
  --name multilevel/gcc12/Os/libmldsa.so \
  <mldsa-native>/binaries/multilevel/gcc12/Os/libmldsa.so \
  > proofs/mldsa_native/gcc12_Os/layout.ml
python3 ../tools/native_proofs_mk.py mldsa_native gcc12_Os \
  > mldsa_native/gcc12_Os/proofs.mk
python3 ../tools/native_link.py mldsa_native gcc12_Os \
  > proofs/mldsa_native/gcc12_Os/link.ml
```

## Compared with gcc 12 -O2

`-Os` neither vectorizes nor inlines much, so the code is smaller and
almost every function is different, but it is compiled from the same
source. The image is 0xa4dc bytes against 0xb650, and has 206 functions
against 192:

 - 26 functions have the same code as at gcc12_O2, up to the addresses;
 - 166 have different code. The polynomial loops that O2 vectorizes
   (`poly_add`, `poly_sub`, `poly_reduce`, the packers and so on) are
   loops over single coefficients, `mldsa_poly_ntt` and
   `mldsa_poly_invntt_tomont` are loops over the layers and the
   butterflies, and five functions differ only in the registers
   (`mldsa{44,65,87}_polyveck_unpack_eta_chknorm` and
   `mldsa_shake{128,256}x4_absorb_once`);
 - 14 are new, because the compiler does not inline them as it does at O2:
   `keccak_absorb` and `keccak_squeeze` (the loops of the absorb and
   squeeze functions of SHAKE), `mld_decompose{44,65,87}` (the
   decomposition of one coefficient, called by `poly_decompose` and
   `poly_use_hint`), `mld_zeroize_1` to `_6` (the function that clears a
   buffer with `memset`, one copy for each of six translation units) and
   `mld_ct_memcmp_1` to `_3`.

The layout names the two functions `keccak_absorb_fn` and
`keccak_squeeze_fn`: `common/fips202/fips202.ml` has a constant
`keccak_absorb`, and a name cannot be both (`gen_layout.py` renames the
functions in its `HOL_CONSTANTS`). A spec file that loads `fips202.ml`
does so before `libmldsa.ml`.

One instruction of the image is not used by the other builds: UDIV, which
divides the index of a matrix entry by the number of columns in
`mldsa{65,87}_polyvec_matrix_expand_eager`, with the number in a register.
It is modelled by `arm_UDIV` in `../../proofs/instruction.ml`. The other
instructions that gcc12_O2 does not use (MVN, SXTB, MSUB, B.LE and STURH)
are modelled as for the other builds.

## The proofs compared with gcc 12 -O2

Every function of the image has a spec file and a proof file with the
theorems FULL, CORRECT and SAFE, 206 pairs against 192 at gcc12_O2. The
statements are those of gcc12_O2, up to the names, except where the code
forces a change:

 - The frames and the stack regions (the regions of the API functions
   contain the largest region of their callees, e.g. 49360 bytes for
   `mldsa44_signature_internal` against 49536 at O2).
 - Callees that reach `memset` include `mld_zeroize_N` and `mld_H`, so
   the statements of their callers have `memset_full_contract` (or
   `memset_ret_full_contract` for those that call `sig_unpack_hints`) as
   hypothesis, with the `memset` entry of the GOT in their regions.
   `poly_use_hint`, which has a stack protector, has the guard as a
   variable. So have the packers `polyeta_pack`, `polyz_pack` and
   `polyt0_pack` and `pack_sig_z`, which calls `polyz_pack`: the packers
   have a stack frame, the stack protector and a call of `mld_zeroize_N`
   that clears their temporary array. At O2 that clearing is a store of
   zeros in the code of the packer, without a call, so there the
   statements of these functions have a frame and the guard, but no
   `memset`.
 - The regions of constants that a callee does not read at -Os (the
   constants of the vectorized code of O2) are not in the lists of
   `memaccess_inbounds`, and the empty region `word 0,0` is, for the
   NULL input of `mld_H`.
 - The MAYCHANGE set of `rej_uniform`, `rej_eta_65` and of the new
   functions `mld_decompose{44,65,87}` is the registers that the code
   changes, as the callers use the others.

The signing code checks z first and then both checks of each row, as at
-O2, so the events of the FULL and SAFE theorems of `signature_internal` and
the functions above it use `mld_sign_declass` of
`common/mldsa_native_sign.ml`, as at -O2. The statements of the API
functions and so the FIPS 204 theorems (`fips204.ml`, `fips204_sign.ml`,
`fips204_verify.ml` and `fips204_safe.ml`) differ from those of O2 only in
the sizes of the stack regions.

The proofs of the functions that share code between parameter sets are
the same up to the constants, layouts and registers; the files of the
other sets were generated from one of them and then adapted. Other
differences in the proofs:

 - `keccakf1600_permute` is proved in the image, not on a separate
   object as at O2: its code is that of `mlkem_keccakf1600_permute` in the
   gcc12_Os image of mlkem-native, and the proof is that one with the
   addresses of this image.
 - `sig_unpack_hints_os.ml` has the tactics of `utils/mldsa_native_hints.ml`
   for the control flow of -Os (`sig_unpack_hints` and, adapted in each
   of its three proof files, `pack_sig_h`); the shared file is
   unchanged.

The jobs of the link file are the 206 proof files. As for the other
builds, the run of `link.ml` closes the contracts of the callees in the
theorems of the API functions.
