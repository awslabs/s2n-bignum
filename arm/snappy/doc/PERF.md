# Performance of the proof of DecompressAllTags<SnappyDecompressionValidator>

The function: 0x6a30, 193 instructions. The spec is
proofs/snappy/gcc12_O2/snappy_decompressor_decompress_all_tags_validator_spec.ml
and its statement is unchanged.

All times are in seconds, measured on one domain (S2N_PAR_DOMAINS=1), so
wall time equals CPU time. They come from the TIMED_TAC wrapper
(common/tactic_timing.ml, turned on by S2N_TACTIC_TIMING=1). Each piece runs
in its own process. A process loads the library in about 97 s (piece total
minus class time).

## Structure (task 2: parallel pieces)

The single proof file (more than 3.5 h serial, never completed) is now split
into pieces, generated by arm/dev/assemble_dat.sh:

- proofs/snappy/dat_validator_lib.ml: the tools, the states, the lemmas and
  the segment tactics (from dev/dat_tools.ml and dev/dat_lib.ml).
- One spec/proof pair per segment T and tag class, each an independent job
  (make -j, the parallel link):
  `..._validator_t_{b,s}_{class}_{spec,proof}.ml`.
  - The contract is dat_class_stmt: the segment statement with the class of
    the tag byte EL 0 rest as an antecedent.
  - B classes: lit, litlong60..63 (the long literal split by header width),
    c1, c2, c4.
  - S classes: lit, litlong, c1, c2, c4.
- `..._validator_proof.ml`: proves ENTRY, L_B and L_S. It combines T_B and T_S
  from the class contracts (DAT_T_FROM_CLASSES_TAC, by the case split
  dat_class_split), then runs the induction (DAT_MAIN_TAC).

A failing piece names itself: its make target fails.

## Case structure per class

Leaves are runs of the tag path from T to an exit or a cut point.

- Copy classes C1, C2, C4:
  - Three failing runs: off = 0, off > produced, and LENGTH out + len > m.
  - The success case runs once per window position after the tag. In B there
    are 4 positions: no refill (5 or more bytes left), RefillTag EMPTY,
    WINDOW with refill_ok, and WINDOW short. In S there are 3 (no "no refill").
  - That makes 7 runs in B and 6 in S (6 or 7 leaves, see below).
  - T_S C4 is killed at setup: it needs 5 bytes and S has fewer than 5.
- LIT:
  - Two failing runs: too few bytes, and over m.
  - Plus the success run per position: 6 or 7 leaves.
- LITLONG:
  - The same, once per header width x = 60..63.
  - In S, the widths that need more bytes than S holds are killed by length.
  - 13 leaves in S, 28 in B.
- Branch conditions that arithmetic cannot decide add a few splits.
  Examples: refill_ok, and data-dependent results of RefillTag.

Each leaf re-runs symbolic execution from T (about 30-45 steps). Symbolic
execution of all leaves of a class costs 3-25 s, about 1-3% of the total.
So sharing the symbolic-execution prefix, or one parametric proof for the
copy classes or for the LITLONG widths, would save very little. Those
designs were not pursued.

What dominated: linear arithmetic over all the state-free facts.

- leaf.normcond decides the if-conditions inside register and memory values at
  each leaf. pc.valdecide and DAT_PC_TAC decide branch conditions. The cut and
  memory checks use the same arithmetic.
- Every one of these calls ran MAP_EVERY MP_TAC facts THEN ARITH_TAC over all
  the facts. At a leaf of T_B C1 that is 150 assumptions and 77 state-free
  facts, including:
  - the model iffs (decode_tags ... = NONE <=> ...), with non-arithmetic atoms;
  - disequalities such as ~(LENGTH rest2 = 0) and ~(off = 0).
- ARITH_TAC case-splits on each of them, also when the goal does not mention
  them.
- Conditions that are not decided were the worst. They made four failing
  attempts (c and ~c, by two methods) before the split, and each attempt was
  a full exponential search.
- Only 30 of the 77 facts are connected to a typical condition.

## Changes (task 3)

1. Relevant arithmetic facts (generic: common/arith_facts.ml).
   - relevant_arith_facts keeps the formulas of linear arithmetic that are
     connected to the goal through shared atoms, transitively. Word operations
     are transparent, so val(word_add x (word k)) meets x and k.
   - It is used by DAT_INT_PROVE (normcond, DAT_PC_TAC), DAT_VAL_DECIDE_PC_TAC
     (a copy of VAL_DECIDE_PC_TAC), DAT_ARITH_TAC, dat_eq (reads), and the
     subset proofs of DAT_MEMACCESS_TAC (DAT_SUBSET_ONE_TAC).
   - The fallbacks are off. They are configurable: dat_arith_all for all
     arithmetic facts, dat_arith_full for all facts.
   - Measured over all classes: the full-facts fallback succeeded 0 of 28 times
     (S_C2, r2). The all-arithmetic fallback succeeded 0 of 288 times (r3, all
     classes) where the relevant facts had failed. Every failure was a
     condition that really cannot be decided and is then split.
2. DAT_NORM_COND_TAC decides each distinct condition once per leaf (memo).
3. Timing instrumentation, generic: common/tactic_timing.ml. Phase timers are
   in dat_lib.ml. Decisions slower than 10 s are printed (SLOWCOND/SLOWPC)
   with the size of the assumption list, the number of facts and the number
   of relevant facts.

## The parallel link

The link (link.ml, 62 jobs) runs the pieces at the same time on the domains
of one process.

First link run (4 domains): T_B C1, C2 and C4 FAILED. Each passed in its own
process. Cause: the tactics kept state across steps in global refs, shared by
the domains:
- dat_copy_rws, the rewrites of a copy class;
- dat_subs, the subset facts;
- dat_eq_facts.

The concurrent copy classes overwrote each other's rewrites. That state is
now per domain (par_local_ref).

Check after the fix (dev/linkdat.ml): all 13 pieces at the same time in one
process on 13 domains are proved in 128 s wall. That is as fast as the
slowest piece alone, so the domains cause no slowdown.

link_costs.tsv now gives the job costs (from the link log), so the link
starts the DAT pieces early. Without it they were estimated by file size and
started last.

The link's wall time is bounded by RawUncompress(Source*, char*): 3137 s,
another stream.

## Remaining hotspots (per class, after)

- leaf.normcond (about 45% of a class): the conditions of the values at a leaf.
  About half of that time goes to conditions that are not decided and then
  stay as conditionals (each fails in about 1 s).
- leaf.cut: 15-20%.
- RefillTag contract calls: 8-10 s each, 2-4 per class.
- The ~97 s library load per process: now the largest single item per
  piece.

Further gains look marginal: perhaps 2x per class, by skipping the decision
of conditions that cannot matter at the leaf. The wall time is already
bounded by load plus about 2 minutes.
